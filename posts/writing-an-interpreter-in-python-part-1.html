Writing an interpreter in Python

Part 1: Scanning

Introduction

This is the first part of a series where we will write an interpreter in Python. No prior compiler experience is assumed, everything is explained from first principles. Additionally, the parts in the series can be generalized to any programming language, meaning that the tools we will use can serve the creation of any arbitrary interpreter. Thus, in this part we will not create a scanner for a specific programming language, rather we will create the functionality so the scanner can scan any source file given the tokens of a language.

Regular expressions

A regular expression is a pattern that describes a multitude of strings. We need regular expression in order to recognize indentifiers in source code since variables, functions and other constructs can be arbitrarily named. For example, the below definitions are all perfectly valid in Python. 

myvar = 123
_lasmdkamdkmsakdmsakdmksadkad = "some string"

So for a scanner to be able to recognize any valid name there needs to be some way to describe the pattern of names. Similarly for numbers and strings; the possible valid options are infinite. Below are some regular expressions and the patterns they recognize. 

A*          Matches A none or more times
A+          Matches A at least once
[0-9]       Matches any number from 0 to 9
[a-z]       Matches any letter from a to z

A can be any letter, string or regular expression. For example, a regular expression that recognizes integer values (allowing leading zeros) looks like so: 

[0-9]+     Matches any number from 0 to 9 at least once

And one that recognizes identifiers with alphanumerics (first letter can't be a number though) and underscores: 

[a-zA-Z_][a-zA-Z0-9_]*

Tokens

The role of the scanner is to convert the source code to a stream of tokens. A token is a just a characterization for the type of the source code strings. For example identifiers, keywords (for, while, in, etc) and numbers are all tokens. We use regular expressions to define tokens and we assign a name to them. 

INTEGER [0-9]+
ID [a-zA-Z_][a-zA-Z0-9_]*
EQ =

Having defined the above tokens, a scanner should receive the statement myvar = 123 and convert it to ID EQ INTEGER.

Writing a scanner

Summarizing thus far, scanners convert source code to tokens by using regular expressions. We need to also clarify what happens when two scanner rules (token definitions) clash with each other, for example both of the below rules recognize the for string, but only one of the two must prevail each time. 

FOR for
ID [a-zA-Z_][a-zA-Z0-9_]*

In order to resolve possible clashes we agree that rules are defined in order of priority so that the FOR rule is prioritized over the ID rule in case of a conflict where the matches are of equal length. Else (i.e. when the matches are not of equal length) the rule with the longest match wins. For example, the FOR rule should match the for keyword because the rule has priority, but the ID rule should match the for13 string because the match is longer than that of FOR's.

Now that we cleared what happens in case of a clash, let's get our hands dirty by writing some code! We'll define some structures to represent tokens and regex rules. 

from dataclasses import dataclass
import re

@dataclass
class Rule:
    name: str
    regex: re.Pattern

    def __init__(self, name: str, regex: str) -> None:
        self.name = name
        self.regex = re.compile(regex)

@dataclass
class Token:
    rule: Rule
    literal: str

Now we can define the scanner. 

from typing import Generator

class _Cursor:
    def __init__(self) -> None:
        self.offset = 0

    def advance(self, consumed: str) -> None:
        self.offset += len(consumed)

class Scanner:
    def __init__(self, rules: list[Rule]) -> None:
        self.rules = rules

    def scan(self, text: str) -> Generator[Token]:
        cursor = _Cursor()

        while cursor.offset < len(text):
            rule, literal = self._longest_match(text, cursor.offset)

            if rule is None:
                cursor.advance(text[cursor.offset])
                continue

            token = Token(rule, literal)
            yield token
            cursor.advance(literal)

    def _longest_match(self, text: str, position: int) -> tuple[Rule | None, str]:
        best_rule = None
        best_literal = ""

        for rule in self.rules:
            literal = rule.regex.match(text, position)
            literal = literal.group() if literal is not None else None

            if literal and len(literal) > len(best_literal):
                best_rule = rule
                best_literal = literal

        return best_rule, best_literal

The scanner receives a list of rules the order of which determines their priority and uses a cursor object to keep track of the current position (offset). Let's try it out! 

rules = [
     Rule("EQ", "="),
     Rule("SEMICOLON", ";"),
     Rule("INT", "[0-9]+"),
     Rule("ID", "[a-zA-Z_][a-zA-Z0-9_]*")
]

scanner = Scanner(rules)
text = "foo = 10; bar = 23; fiz = 33;"
for token in scanner.scan(text):
    print(token.rule.name)

Running the above should output: 

ID          
EQ          
INT         
SEMICOLON   
ID          
EQ          
INT         
SEMICOLON   
ID          
EQ          
INT         
SEMICOLON

That's really it, to be honest. There's no compiler magic under the hood or anything arcane going on here, just some good ol' code that does what it's supposed to. Of course this is not a production-ready scanner, it does not track the location of the tokens or handle unmatched tokens, but it serves our purpose of demonstrating how a scanner works.
