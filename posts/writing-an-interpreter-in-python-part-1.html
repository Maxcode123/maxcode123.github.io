Writing an interpreter in Python

Part 1: Scanning

Introduction

This is the first part of a series where we will write an interpreter in Python. No prior compiler experience is assumed, everything is explained from first principles. Additionally, the parts in the series can be generalized to any programming language, meaning that the tools we will use can serve the creation of any arbitrary interpreter. Thus, in this part we will not create a scanner for a specific programming language, rather we will create the functionality so the scanner can scan any source file given the tokens of a language.

Regular expressions

A regular expression is a pattern that describes a multitude of strings. We need regular expression in order to recognize indentifiers in source code since variables, functions and other constructs can be arbitrarily named. For example, the below definitions are all perfectly valid in Python. 

myvar = 123
_lasmdkamdkmsakdmsakdmksadkad = "some string"

So for a scanner to be able to recognize any valid name there needs to be some way to describe the pattern of names. Similarly for numbers and strings; the possible valid options are infinite. Below are some regular expressions and the patterns they recognize. 

A*          Matches A none or more times
A+          Matches A at least once
[0-9]       Matches any number from 0 to 9
[a-z]       Matches any letter from a to z

A can be any letter, string or regular expression. For example, a regular expression that recognizes integer values looks like so: 

[0-9]+     Matches any number from 0 to 9 at least once

And one that recognizes identifiers with alphanumerics (first letter can't be a number though) and underscores: 

[a-zA-Z_][a-zA-Z0-9_]*

Tokens

The role of the scanner is to convert the source code to a stream of tokens. A token is a just a characterization for the type of the source code strings. For example identifiers, keywords (for, while, in, etc) and numbers are all tokens. We use regular expressions to define tokens and we assign a name to them. 

INTEGER [0-9]+
ID [a-zA-Z_][a-zA-Z0-9_]*
EQ =

Having defined the above tokens, a scanner should receive the statement myvar = 123 and convert it to ID EQ INTEGER.

Writing a scanner

Summarizing thus far, scanners convert source code to tokens by using regular expressions. We need to also clarify what happens when two scanner rules (token definitions) clash with each other, for example both of the below rules recognize the for string, but only one of the two must prevail each time. 

FOR for
ID [a-zA-Z_][a-zA-Z0-9_]*

In order to resolve possible clashes we agree that rules are defined in order of priority so that the FOR rule is prioritized over the ID rule in case of a conflict.
